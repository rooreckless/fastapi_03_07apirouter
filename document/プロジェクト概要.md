# プロジェクト概要

## 概要

このプロジェクトは、**ドメイン駆動設計（DDD）とクリーンアーキテクチャ**を適用したFastAPIベースのWebアプリケーションです。商品カテゴリ管理、商品管理、および認証機能を持つRESTful APIを提供しています。

### 主要技術スタック

- **バックエンド**: FastAPI (Python 3.12)
- **データベース**: PostgreSQL (非同期SQLAlchemy)
- **認証**: JWT (JSON Web Token) + OAuth2
- **コンテナ化**: Docker & Docker Compose
- **テスト**: pytest + pytest-mock + pytest-cov
- **依存管理**: uv (Python Package Manager)

---

## アーキテクチャ概要

本プロジェクトは**レイヤードアーキテクチャ**に基づいて設計されており、以下の層に分かれています：

```
┌─────────────────────────────────────────┐
│           Presentation Layer            │  ← FastAPI Routers
├─────────────────────────────────────────┤
│           Application Layer             │  ← Use Cases
├─────────────────────────────────────────┤
│             Domain Layer                │  ← Entities & Value Objects
├─────────────────────────────────────────┤
│          Infrastructure Layer           │  ← SQLAlchemy, External APIs
└─────────────────────────────────────────┘
```

## ディレクトリ構造と役割

### `/app` - メインアプリケーションディレクトリ

#### `main.py`
- **役割**: FastAPIアプリケーションのエントリーポイント
- **機能**:
  - FastAPIアプリケーションインスタンスの作成
  - 各ルーター（categories, items, auth）の登録
  - Swagger UI設定（認証機能付き）
  - アプリケーション全体の設定

---

### `/app/abstract_repository` - リポジトリインターフェース

#### `category_repository.py`
- **役割**: カテゴリリポジトリの抽象インターフェース
- **機能**: CategoryRepositoryの抽象基底クラス定義

#### `item_repository.py`
- **役割**: 商品リポジトリの抽象インターフェース
- **機能**: ItemRepositoryの抽象基底クラス定義

#### `user_repository.py`
- **役割**: ユーザーリポジトリの抽象インターフェース
- **機能**: UserRepositoryの抽象基底クラス定義

**設計原則**: 依存性逆転の原則（DIP）により、上位層が下位層の実装に依存しないよう抽象化

---

### `/app/core` - アプリケーション共通機能

#### `config.py`
- **役割**: アプリケーション設定管理
- **機能**:
  - JWT秘密鍵設定
  - トークン有効期限設定
  - 環境変数からの設定読み込み

#### `jwt.py`
- **役割**: JWT（JSON Web Token）処理
- **機能**:
  - アクセストークン生成 (`create_access_token`)
  - トークンデコード・検証 (`decode_token`)
  - トークン有効期限管理

#### `security.py`
- **役割**: セキュリティ関連処理
- **機能**:
  - パスワードハッシュ化 (`hash_password`)
  - パスワード検証 (`verify_password`)
  - bcrypt暗号化アルゴリズム使用

---

### `/app/db` - データベース設定

#### `base.py`
- **役割**: SQLAlchemy基底クラス定義
- **機能**: declarative_baseによるORMマッピング基底提供

#### `database.py`
- **役割**: データベース接続管理
- **機能**:
  - 非同期SQLAlchemyエンジン設定
  - データベースセッション管理
  - 依存性注入用セッション取得関数 (`get_db`)

---

### `/app/domain` - ドメイン層

ビジネスロジックとドメインエンティティを含む、アプリケーションの核心部分。

#### `/domain/category`
- **`category.py`**: カテゴリエンティティ（ビジネスロジック含む）
- **`value_objects.py`**: CategoryName値オブジェクト（バリデーション機能付き）
- **`__init__.py`**: カテゴリドメインパッケージのエクスポート設定

#### `/domain/items`
- **`item.py`**: 商品エンティティ（カテゴリとの関連管理含む）
- **`value_objects.py`**: ItemName, CategoryId値オブジェクト
- **`__init__.py`**: 商品ドメインパッケージのエクスポート設定

#### `/domain/user`
- **`user.py`**: ユーザーエンティティ（認証・認可機能含む）
- **`value_objects.py`**: UserId, MailAddress, HashedPassword, FullName値オブジェクト
- **`__init__.py`**: ユーザードメインパッケージのエクスポート設定

**設計原則**: ドメインエンティティはビジネスルールを表現し、他の層に依存しない純粋なビジネスロジック

---

### `/app/dto` - データ転送オブジェクト

#### `category_dto.py`
- **役割**: カテゴリ関連のDTO（Data Transfer Object）
- **機能**:
  - `CategoryCreateDTO`: カテゴリ作成用データ
  - `CategoryReadDTO`: カテゴリ読み取り用データ
  - `CategoryUpdateDTO`: カテゴリ更新用データ
  - Pydanticバリデーション機能付き

#### `item_dto.py`
- **役割**: 商品関連のDTO
- **機能**:
  - `ItemCreateDTO`: 商品作成用データ
  - `ItemReadDTO`: 商品読み取り用データ
  - `ItemUpdateDTO`: 商品更新用データ
  - カテゴリ関連付け管理

#### `user_dto.py`
- **役割**: ユーザー関連のDTO
- **機能**:
  - `UserCreateDTO`: ユーザー登録用データ
  - `UserReadDTO`: ユーザー情報読み取り用データ
  - `UserLoginDTO`: ログイン用データ
  - `TokenDTO`: 認証トークン用データ
  - メールアドレス・パスワードバリデーション

---

### `/app/infrastructure` - インフラストラクチャ層

外部システムとの接続・データ永続化を担当。

#### `/infrastructure/sqlalchemy`

##### `/models` - ORMモデル
- **`category_orm.py`**: カテゴリテーブルのORMマッピング
- **`item_orm.py`**: 商品テーブルのORMマッピング
- **`user_orm.py`**: ユーザーテーブルのORMマッピング
- **`item_category_association.py`**: 商品-カテゴリ関連テーブル（多対多関係）

##### `/mappers` - ドメインエンティティ⇔ORMマッピング
- **`category_mapper.py`**: CategoryエンティティとCategoryORMの相互変換
- **`item_mapper.py`**: ItemエンティティとItemORMの相互変換
- **`user_mapper.py`**: UserエンティティとUserORMの相互変換

##### `/repo_imples` - リポジトリ実装
- **`category_repo_impl.py`**: SQLAlchemyCategoryRepository実装
- **`item_repo_impl.py`**: SQLAlchemyItemRepository実装
- **`user_repo_impl.py`**: SQLAlchemyUserRepository実装

**設計原則**: ドメイン層が Infrastructure層に依存しないよう、抽象リポジトリを実装

---

### `/app/routers` - プレゼンテーション層

FastAPI ルーターによるHTTPエンドポイント定義。

#### `auth.py`
- **役割**: 認証関連エンドポイント
- **エンドポイント**:
  - `POST /auth/register` - ユーザー登録
  - `POST /auth/login` - アプリ用ログイン
  - `POST /auth/token` - OAuth2トークン取得
  - `GET /auth/me` - 現在のユーザー情報取得
- **機能**: JWT認証、パスワード検証、トークン発行

#### `categories.py`
- **役割**: カテゴリ管理エンドポイント
- **エンドポイント**:
  - `GET /categories` - カテゴリ一覧取得
  - `POST /categories` - カテゴリ作成
  - `GET /categories/{id}` - カテゴリ詳細取得
  - `PUT /categories/{id}` - カテゴリ更新
- **機能**: CRUD操作、依存性注入によるユースケース実行

#### `items.py`
- **役割**: 商品管理エンドポイント
- **エンドポイント**:
  - `GET /items` - 商品一覧取得
  - `POST /items` - 商品作成
  - `GET /items/{id}` - 商品詳細取得
  - `PUT /items/{id}` - 商品更新
  - `PUT /items/{id}/name_body` - 商品名のみ更新
  - `DELETE /items/{id}` - 商品削除
- **機能**: カテゴリ関連付け管理、商品CRUD操作

**設計原則**: ルーターは薄い層とし、ビジネスロジックはユースケース層に委譲

---

### `/app/usecases` - アプリケーション層

ビジネスユースケース（アプリケーションサービス）の実装。

#### `/usecases/category`
- **`create_category.py`**: カテゴリ作成ユースケース
- **`get_category.py`**: カテゴリ取得ユースケース
- **`list_categories.py`**: カテゴリ一覧取得ユースケース
- **`update_category.py`**: カテゴリ更新ユースケース

#### `/usecases/item`
- **`create_item.py`**: 商品作成ユースケース
- **`delete_item.py`**: 商品削除ユースケース
- **`get_item.py`**: 商品取得ユースケース
- **`list_items.py`**: 商品一覧取得ユースケース
- **`update_item.py`**: 商品更新ユースケース
- **`update_item_name.py`**: 商品名更新ユースケース

#### `/usecases/user`
- **`authenticate_user.py`**: ユーザー認証ユースケース
- **`create_user.py`**: ユーザー作成ユースケース
- **`get_user.py`**: ユーザー取得ユースケース

**設計原則**: 各ユースケースは単一責任を持ち、ドメインエンティティとリポジトリを協調させてビジネスロジックを実行

## 認証・認可システム

### 認証フロー
1. **ユーザー登録**: `/auth/register` でアカウント作成
2. **ログイン**: `/auth/login` または `/auth/token` でJWTトークン取得
3. **認証が必要なエンドポイント**: `Authorization: Bearer <token>` ヘッダーでアクセス
4. **ユーザー情報取得**: `/auth/me` で現在のユーザー情報を取得

### セキュリティ機能
- **パスワードハッシュ化**: bcryptアルゴリズム使用
- **JWT トークン**: HS256アルゴリズムで署名
- **トークン有効期限**: 設定可能（デフォルト30分）
- **OAuth2準拠**: Swagger UIでの認証テスト対応

## テスト戦略

### テストカバレッジ: 91%

### テスト構成
- **単体テスト**: 各層の個別機能テスト
- **結合テスト**: データベースを含む結合テスト
- **APIテスト**: HTTPエンドポイントのテスト

### テスト対象
1. **ドメイン層**: エンティティと値オブジェクトのビジネスルール
2. **アプリケーション層**: ユースケースの業務フロー
3. **インフラ層**: リポジトリ実装とORMマッピング
4. **プレゼンテーション層**: ルーターのHTTPレスポンス
5. **認証システム**: JWT, パスワード管理, セキュリティ機能

### テスト原則
- pytest + pytest-mock使用（unittest.mock不使用）
- 日本語docstring + 英語関数名
- 正常系・異常系・エッジケース網羅
- AsyncMock使用による非同期処理テスト

## 設計原則とベストプラクティス

### DDD（ドメイン駆動設計）
- **ドメインエンティティ**: ビジネスルールをカプセル化
- **値オブジェクト**: 不変オブジェクトでドメイン概念を表現
- **リポジトリパターン**: データアクセスの抽象化
- **ユースケース**: アプリケーション固有のビジネスフロー

### クリーンアーキテクチャ
- **依存性逆転**: 上位層が下位層の抽象に依存
- **関心の分離**: 各層が明確な責任を持つ
- **テスタビリティ**: 依存性注入によるテスト容易性

### FastAPI ベストプラクティス
- **型ヒント**: 完全な型安全性
- **Pydantic**: 自動バリデーションとシリアライゼーション
- **依存性注入**: 疎結合な設計
- **非同期処理**: async/await による高パフォーマンス
